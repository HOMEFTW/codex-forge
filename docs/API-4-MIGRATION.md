# Forge API 4 迁移

适用：Codex Forge 0.6.0。官方客户端目标仍为 `26.1103.7773.0`，没有因此升级官方客户端。API 4 与安装包版本、清单 schema 是独立版本。

## 变化

- 清单、SDK 与宿主上下文使用 `apiVersion: 4`；插件清单 `schemaVersion: 1`、更新协议 `schemaVersion: 3`、Nexus 能力版本 1 保持。
- 新增 `conversation.predict` 权限及 `prompt-prediction@1` 能力，仅限内置 `forge.prompt-prediction`。独立插件不能申请它们，也没有新增公共预测调用或任意原生 RPC。
- 自动预测由宿主可信回合完成事件触发，当前线程采样、空草稿确认、取消、灰字、Tab 接受和原生预测避让均由宿主管理。默认启用，可在插件设置中关闭；调用可能消耗当前模型提供商额度。
- 通过可信原生设置与账号元数据识别 Pro（`pro/prolite/promax`）：原生预测开关打开时暂停 Forge 采样并取消请求，保留插件启用偏好。关闭后恢复当前已观察且未尝试过的完成回合；失败或取消的采样不重试。原生开关打开且账号未知时等待；开关明确关闭时不依赖订阅结果。
- 公共 composer、events、Nexus 等 API 3 操作和结果继续保留，但插件启用仍要求 API 严格相等。

## 独立插件迁移

1. 更新到当前 SDK，重新检查 TypeScript 类型和实际运行行为。
2. 保持插件 ID，更新插件版本和 `apiVersion: 4`；Forge 兼容范围按实际验证填写，例如 `>=0.6.0 <0.7.0`。Codex 版本仅填写验证过的客户端。
3. 验证安装、启用、设置、存储、界面和所调用 API；Nexus 另需检查连接目录、revision 读写保护及权限。
4. 重新打包并生成更新清单与摘要。用户直接导入新版 ZIP/7z/JSON 包，覆盖升级仍先暂存、重启生效；权限变化须重新审阅。

API 1/2/3 清单仍能读取并显示不兼容诊断，设置和存储保留，但不能在 API 4 宿主启用。宿主不会替作者修改 API 或扩大兼容范围。星枢 Nexus 是独立插件，需要其作者提供 API 4 版本，本次未修改该项目。

## 安装宿主

已发布的 0.5.x（API 3）更新器不接受 API 4 清单。首次迁移需手动运行新版 MSI、将新版便携 ZIP 解压到便携目录，或运行新版独立更新器。独立更新器仍为备用入口，常规升级流程保持不变；启用插件不兼容会阻止自动更新计划。正式包见 [0.6.0 发布页](https://github.com/HOMEFTW/codex-forge/releases/tag/v0.6.0)。
