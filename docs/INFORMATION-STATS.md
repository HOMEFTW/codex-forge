# 信息统计与模型指纹

## 当前实现

使用 lm-detector 的 69 类参考库与配套 `shared-detector-v2` 离线评分器，固定上游提交 `a7e9d3056e019827904dd50722c20b4a0c896738`。库内有 15 个模型家族、2,560 条参考回答，数据日期 2026-11-11。数据、二进制评分器、固定挑战和档位元数据通过 SHA-256 绑定；原始评分源码与 MIT 许可在 `vendor/lm-detector`。

运行检测使用三个独立临时会话、空目录和关闭的工具/MCP 能力，保留当前模型、提供商和思考强度，不复制主聊天历史。挑战取自上游 clean environment-01，要求 218、233、247 个 1–355 整数。沿用 Codex 自身提供商连接，不接入第三方网页代理，不需要单独的检测服务密钥。

## 自动与手动

- “模型检测”页和插件设置页都能控制“空闲时自动检测”，默认关闭。
- 开启后每 10 秒检查当前已连接聊天；只有日志已确认空闲、没有已知运行回合且模型、档位、渠道身份可确认时才采样。
- 每次发送三个模型请求，使用当前思考强度，可能消耗额度；任何时刻仅运行一个指纹任务。
- 相同渠道身份、声明模型、思考强度、数据与挑战版本的结果可跨聊天和进程重启复用 24 小时。端点、账号或凭据变化会产生不同渠道摘要；共享类的两个声明型号也分别缓存。
- 失败或取消会保存本地尝试状态并冷却，避免自动循环请求；手动“运行检测”可以立即重试，不依赖自动开关。
- 新回合开始、离开对应聊天、关闭自动开关或停用插件会取消自动检测。取消后到达的回答不会作为新结果保存，不中断主任务。
- 渠道、凭据和账号信息只在宿主内参与摘要计算，不写入统计记录、不通过统计 IPC 返回。身份无法确认时自动检测等待，手动采样仍可使用。

## 结果与思考强度

`gpt-6-astra` 和 `gpt-6.1-sol` 共用参考类别，显示为 `gpt-6-astra/6.1-sol`，提示“共享类别，无法区分”。命中不能认证独立型号。旧 Claude 连字符拼写映射到对应类别，不合并其他 GPT 型号。

只有三条标准挑战有效、校准匹配、当前思考强度在声明类别参考批次中有显式记录时，才显示参考库内概率。其余情况显示候选排名和得分，并解释条件差异。例如 OpenAI 的重要参考批次使用 low；当前 xhigh 检测仍使用 xhigh，显示“仅供参考”，不自动改用 low，不因排名差异标红。

粘贴或导入的外部回答没有已确认的标准挑战条件，只作本地参考排名。少于三份有效回答不计算校准概率；不符合序列形态检查的回答不排名。旧评分历史保留，但显示“旧版结果，需重测”，不能成为当前告警。

可比较条件下，三份有效回答、第一候选库内概率至少 80%、声明类别概率至多 20% 时提示“疑似不一致”，侧栏标红。共享类别、条件不同、库外声明、弱证据和过期结果不据此标红。

概率只在候选库内分配，实际库外模型也可能得到高排名。Codex 系统提示与参考 API 环境不同，不能直接套用上游准确率。“配置变更记录”只读取日志中的型号、思考强度、设置和窗口，不消耗额度，也不能证明服务端模型身份。

## 构建与验证

`npm run build` 从固定上游源码生成 CommonJS 评分模块，将运行模块、参考库与二进制评分器复制到 `dist/fast-extension`。不依赖在线服务或本机重训。

验证详情见 `docs/VALIDATION.md` 的对应条目。本轮使用参考回答固定样例和 localhost 模拟服务，样例用于功能回归，不作为独立识别准确率评测。没有替换正在运行的客户端，也没有向真实远端模型发起检测请求。
